# 日常 · Health

记录每天的饮食、锻炼和身体变化。适配手机与电脑的个人健康手账。

## 在线使用

[打开日常 Health](https://aaaa12342.github.io/health/)

- **饮食**：自定义食物库；早、中、晚餐及加餐多选食物；临时添加、修改份量、备注；按份量折算能量、蛋白质、脂肪、碳水、膳食纤维及钠。
- **每日营养标准**：在饮食或总览的摄入区域点击「设置标准」，填写自己的每日标准；显示已记录摄入与标准的比例、差额。留空不比较；零标准仅显示差额，不计算百分比。标准通用于所有日期，并随备份导出；旧版备份可正常导入。
- **锻炼**：自定义动作、组数、每组次数、秒数或分钟数；多选训练、临时添加；记录时长、感受和当日体重。
- **总览**：查看一天的饮食与训练、营养合计；记录体重、腰围、臀围、胸围、大腿围及上臂围；用日历回看历史，查看截至所选日期近 7/30 天的趋势。

体重与围度分开录入：「记录体重」只显示体重；「记录围度」只显示五项围度。保存或清除一类数据不会改动另一类，趋势图中的空记录入口也按相应指标打开。
- **备份与恢复**：导出/导入 JSON；恢复前校验并展示摘要、要求确认；保存导入前副本，可恢复上次导入前的记录。

## 数据保存与云同步

未登录时，所有记录继续保存在当前浏览器，不自动上传。登录后使用 Reading 的同一 Supabase 账号，健康数据存在独立数据表，不混入阅读记录。

**首次使用需要在 Reading 的 Supabase SQL Editor 执行 [health-sync.sql](supabase/health-sync.sql)。** 设置与迁移见 [云同步说明](docs/cloud-setup.md)。网页中的「同步与账号」可以登录、刷新、退出及将本机记录主动合并到云端；本机原件保留。云端写入采用版本号保护，避免两台设备静默覆盖；失败保留表单，不回退为本地保存。切回页面且没有编辑表单时自动刷新。

导出/导入处理当前模式的数据；云导入会明确确认替换当前账号记录，并在本机保留账号隔离的恢复副本。清理本机数据前请备份；云记录不写入 GitHub。相同域名下两个应用共享 Supabase 登录会话，退出会影响同浏览器的 Reading 会话。

每个食物的营养对应指定的基准数量和单位，按实际食用数量折算。空营养表示未知；历史记录保留当时的快照。体重与围度分开填写；趋势缺失日期留空，不按零计算。

## 本地运行

无需安装项目依赖。Supabase SDK 已随网页提供，不依赖外部 CDN。

```sh
python -m http.server 4173 --bind 127.0.0.1
```

然后访问 `http://127.0.0.1:4173/`。请通过 HTTP 服务打开，直接双击 `index.html` 的 `file://` 地址无法加载 ES modules。

数据逻辑及语法检查（Node.js 22+）：

```sh
node --test tests/*.test.js
node --check app.js
node --check domain.js
node --check cloud-store.js
```

浏览器回归脚本为 `tests/browser.cjs`，需要单独提供 Playwright 包及本机 Edge，且先启动上述本地服务。测试使用隔离浏览器上下文，临时截图与备份写入被忽略的 `.qa/`，不改用户记录。可用 `BROWSER_CHANNEL=chrome` 切换 Chrome。

## 部署

GitHub Pages 使用 `main` 分支根目录，无构建步骤。`.nojekyll` 禁用 Jekyll 处理。GitHub Actions 在推送和 PR 时执行语法及数据测试。

可选隔离 SQL 权限测试：安装独立的 PGlite 测试运行时，将 PGLITE_MODULE 指向其模块路径，运行 `node tests/sql-permissions.cjs`。不需要把它安装成网站运行依赖。云浏览器模拟运行 `node tests/cloud-browser.cjs`，使用与原浏览器回归相同的 Playwright 环境及本地服务。
