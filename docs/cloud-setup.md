# 健康记录云同步：一次初始化

沿用 Reading 的 Supabase 项目、邮箱和密码。连接所用的公开 key 已配置；无需建立新项目，也无需修改 Reading 的数据表或登录 Site URL。

## 1. 初始化健康表

1. 打开 Reading 所用项目的 Supabase Dashboard → SQL Editor → New query。
2. 复制并完整运行 [health-sync.sql](../supabase/health-sync.sql)。
3. 确认成功后刷新 [健康记录](https://aaaa12342.github.io/health/)。

脚本只新增 health_journals 表和 save_health_journal 函数，并设置 RLS；不会修改 books、reading_sessions。可重复运行，不清空数据。网页仅有公开连接 key，无法代替数据库管理员执行建表 SQL。

## 2. 登录与迁移

- 点击「同步与账号」，使用 Reading 的邮箱、密码登录；同域且 Reading 已登录时可能直接沿用现有会话。
- 未登录时仍是原来的本地记录，登录后显示当前账号的云端记录。二者不自动覆盖。
- 在保存原本地记录的浏览器登录后，打开「同步与账号」→「合并本机记录到云端」→确认。
- 本机原件保留。迁移遇到相同 ID 不同内容、同日身体数据或备注不同值时整体取消，并提示先导出备份处理；不会悄悄选一份覆盖。
- 手机或其他电脑登录相同账号，点「重新同步」查看记录。

## 3. 保存与冲突

每次保存必须获得云端确认；失败会保留弹窗及输入，不会回退到本地并冒充同步成功。云端读取失败会阻止覆盖写入。

同一账号整份日志使用版本号保护；另一设备已更新时，旧设备保存会提示冲突。保留自己的输入内容，关闭表单后重新同步，再重新编辑。当前版本采用在线云保存，断网时不能提交云端记录；仍可退出后使用独立本地模式，但不会自动合并离线操作。

切回页面且未编辑表单时自动读取；也可主动重新同步。退出共享账号会回到本机记录。同域下与 Reading 共用会话，退出也会影响该浏览器的 Reading 登录。

## 4. 备份与数据范围

食物库、动作库、饮食、训练、备注、体重围度、营养标准一起同步。备份导出当前模式的数据；云端导入需要确认替换当前账号日志。导入前副本在本机按账号隔离保存。

公开 GitHub 仓库仅保存网页、SQL 和公开连接配置，不保存私人日志、密码或登录 token。

## 验证边界

本地领域测试、云接口模拟和隔离 SQL 权限测试不能代替真实 Supabase 验收。初始化后还需用同账号在两个浏览器添加、编辑并同步；用另一个账号确认看不到第一个账号的记录。当前未持有你的数据库管理连接或网页登录凭据。
