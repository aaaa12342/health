# 健康记录云同步
用户确认复用 Reading 的 Supabase 项目和账号。网页仍由 GitHub Pages 托管。

- 本地模式保留原 daily-health:v1；云端按 user_id 存于独立 health_journals 表，不读写 Reading 表。
- 一账号一份完整版本化日志快照，revision 乐观锁；保存为单个事务，所有食物、动作、日期及标准一起生效，冲突拒绝覆盖。
- 未登录读写本地；登录读写云端；云写入失败不回退本地或显示成功。读取失败阻止写入，避免空状态覆盖；账号切换时丢弃旧请求返回。
- 本机数据迁移采用 ID 去重、非冲突合并；同 ID 不同内容、同日备注/身体/标准不同值会整体拒绝，先导出处理。不会自动迁移。
- 云导入为明确确认的全量替换，保留按账号隔离的导入前恢复副本。
- 同步按钮主动刷新，切回页面且无编辑草稿时自动刷新。断网保留表单，提示重试，不宣称离线云同步。
- 沿用 Reading 的默认 Supabase session key，账号相同；若两个页面处于同一域，可共享登录状态。登录/退出会影响同源下同项目的 Reading 会话，界面说明。
- SQL 创建专用表、RLS 和 CAS RPC；只使用公开 anon/publishable key，禁止服务密钥。
- 验证：数据合并/冲突/版本/账号切换竞态单元测试，浏览器模拟两个客户端和错误，旧流程回归；真实表创建、登录、跨设备和多账号权限单独验收。
